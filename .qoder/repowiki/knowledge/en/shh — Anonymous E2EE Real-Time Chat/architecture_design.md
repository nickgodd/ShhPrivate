Two-tier monorepo: `server/` (Node.js, single dependency `ws`) serves static files from `public/` and upgrades HTTP to WebSocket; `public/` is a zero-build browser client. The two halves communicate exclusively via a small set of JSON messages (`pow_challenge`, `create_session`, `search`, `contact_request(_sent|_failed)`, `contact_response`, `message`, `end_chat`, `ping` plus server replies) defined in the README's protocol section. The server owns session state, PoW challenge issuance, rate-limiting, and message relay but never sees plaintext or keys; the client owns the full crypto stack (Web Crypto API) and derives per-chat AES-256-GCM keys via ECDH+HKDF with forward secrecy. Deployment targets Railway with HTTPS/WSS auto-provisioned so the client can derive `wss://location.host` at runtime.
