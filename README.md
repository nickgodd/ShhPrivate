# shh.

Анонимный чат в реальном времени со **сквозным шифрованием (E2EE)**. Только переписка, ничего лишнего.

- **Ничего не сохраняется.** Ни базы данных, ни логов, ни `localStorage`/cookies. Всё живёт только в оперативной памяти браузера и сервера. IP-адреса не пишутся.
- **Сервер видит только шифртекст.** Он умеет лишь пересылать базовые blob'ы между клиентами. Ключи и открытый текст на сервер не попадают никогда.
- **Черно-белый минимализм, только тёмная тема.** Быстрая загрузка, нет внешних шрифтов, трекеров и CDN.
- **Криптография — на клиенте**, на нативном `Web Crypto API` (без сторонних библиотек).

## Запуск локально

Нужен Node.js 18+.

```bash
npm install      # ставит только ws
npm start        # поднимет сервер на http://localhost:3000
```

Откройте `http://localhost:3000` в двух разных браузерах/вкладках — это будут два собеседника.

Для разработки с автоперезапуском:

```bash
npm run dev
```

> Криптография `Web Crypto` требует защищённого контекста. `http://localhost` браузер считает защищённым, поэтому локально всё работает. В продакшене обязателен HTTPS/WSS (Railway даёт его из коробки).

## Деплой на Railway

Проект уже подготовлен:

- **Порт** берётся из окружения: `const PORT = Number(process.env.PORT) || 3000;` (`server/index.js`).
- **Скрипт запуска** — `npm start` → `node server/index.js` (Railway использует `start` из `package.json`).
- **WebSocket-адрес** клиент вычисляет сам через `location.host`, поэтому он автоматически совпадает с доменом Railway (`wss://<ваш-домен>` при HTTPS):

  ```js
  // public/app.js
  const WS_URL = () => `${location.protocol === 'https:' ? 'wss' : 'ws'}://${location.host}`;
  ```

- **`.gitignore`** исключает `node_modules/`, `.env` и логи.

Шаги:

1. Запушьте репозиторий в GitHub.
2. В Railway создайте проект из репозитория (New Project → Deploy from GitHub repo).
3. Railway сам определит Node.js, выполнит `npm install` и `npm start` и выдаст публичный HTTPS-URL (term-сервис). TLS-терминация включена автоматически → клиент подключится по `wss://`.
4. При необходимости выставьте переменную окружения `PORT` (по умолчанию Railway сам задаёт `PORT`, и приложение её читает).

Никаких дополнительных сервисов (БД, кэш) не требуется — всё в памяти процесса.

## Как пользоваться

1. **Создать сессию** — на стартовом экране одна кнопка. Перед созданием сервер выдаёт **PoW-задачу** (Proof-of-Work капчу): браузер должен подобрать nonce, чтобы `SHA-256(challenge:nonce)` начинался с нужного числа нулей. Это защита от ботов без внешних сервисов вроде Turnstile.
2. **Профиль** (круглая кнопка слева сверху) — показывает ваш идентификатор и публичный ключ (по умолчанию скрыты, есть «показать»/«копировать»). Кнопка **«Выйти»** создаёт новую сессию (новые ключи, всё стирается).
3. **Поиск** по 12-символьному идентификатору собеседника → **«Запрос»** на диалог.
4. Получатель видит карточку запроса и может **Принять** или **Отклонить**. Уведомление исчезает после принятия/отказа, а также после завершения чата — сервер рассылает событие обеим сторонам.
5. В чате справа сверху **«⋯» → «Завершить чат»**: чат мгновенно и полностью удаляется у обеих сторон (клиент и сервер), собеседник получает уведомление.
6. **Отпечаток ключа (fingerprint)** виден в шапке чата и в меню «⋯». Собеседники сверяют его по отдельному защищённому каналу — если коды совпадают, посредника (MITM) нет.

Сессия живёт, пока открыта вкладка. При закрытии вкладки/обрыве WS сервер удаляет сессию, её чаты и связи (есть короткий grace-период на перезагрузку страницы). Сообщения **не хранятся**: если получатель офлайн, доставка не происходит (очередей нет).

## Криптосхема (кратко)

Всё выполняется в браузере, на `crypto.subtle`.

| Шаг | Технология |
|-----|------------|
| Идентификация сессии | эфемерная пара **X25519** на сессию, приватный ключ не покидает браузер |
| Идентификатор | случайные 12 символов **base32** из CSPRNG (`crypto.getRandomValues`) |
| Общий секрет | **ECDH** на эфемерных ключах (свежая пара на каждый чат → forward secrecy) |
| Вывод ключа | **HKDF-SHA256** (salt = конкатенация отсортированных эфемерных публичных ключей, info = `shh-chat-v1`) → **AES-256** |
| Шифрование сообщений | **AES-256-GCM** с уникальным 96-битным nonce на каждое сообщение (`iv ‖ ciphertext ‖ tag`) |
| Отпечаток (MITM-проверка) | `SHA-256` от.identity+ephemeral публичных ключей обеих сторон, показывается как 4 группы hex |
| Защита от ботов | **PoW** на `SHA-256` (подбор nonce) перед созданием сессии |

### Установление ключа чата

1. Инициатор создаёт **эфемерную** пару `EphA` и вместе с запросом на диалог отправляет `EphA_pub` и `IdentityA_pub`.
2. Принятие запроса: респондер создаёт свою **эфемерную** пару `EphB` и отправляет `EphB_pub`.
3. Обе стороны считают общий секрет: `ECDH(EphA_priv, EphB_pub) == ECDH(EphB_priv, EphA_pub)` и через **HKDF** выводят один и тот же AES-256-GCM ключ.
4. Все сообщения шифруются этим ключом с **уникальным nonce**. Приватные эфемерные ключи хранятся только в памяти вкладки.

Так как на каждый чат создаются новые эфемерные ключи, компрометация одной сессии не вскрывает другие (**forward secrecy** на уровне чата). Сервер при этом пересылает только базовые blob'ы шифртекста и не имеет ни ключей, ни открытого текста.

### Совместимость кривой

X25519 в `Web Crypto` поддерживается современными Chrome/Edge/Firefox/Safari. Если движок не поддерживает X25519, клиент прозрачно откатывается на **P-256 ECDH** — кривая определяется по длине публичного ключа (32 байта = X25519, 65 байт = P-256), поэтому обе стороны автоматически договариваются об одной кривой. HKDF и AES-256-GCM остаются неизменными.

## Безопасность и ограничения

- **Размер сообщения ≤ 2 КБ** — проверяется и на клиенте (`crypto.js: overSize`), и на сервере (`ws.js: validCipher`).
- **Rate limiting** на поиск, запросы на диалог и сообщения (токен-бакеты на соединение) — защита от перебора идентификаторов и спама.
- **Только HTTPS/WSS** в проде; строгая **CSP** (`default-src 'self'`, без внешних источников, `frame-ancestors 'none'` и т.д.) и набор security-заголовков (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, HSTS) — в `server/index.js`.
- **Без логов и без БД.** Сервер не сохраняет IP, содержимое или метаданные сообщений на диск.
- **Без store-and-forward.** Офлайн-получателю сообщение не доставляется и в очередь не ставится.

## Протокол WebSocket (для справки)

Клиент → сервер: `pow_challenge`, `create_session`, `search`, `contact_request`, `contact_response`, `message`, `end_chat`, `ping`.
Сервер → клиент: `pow_challenge`, `session_created`, `search_result`, `contact_request(_sent|_failed)`, `contact_response`, `message`, `chat_ended`, `peer_online|peer_offline`, `error`, `pong`.

Сервер оперирует только идентификаторами и шифртекстом; поля `publicKey`/`ephPub` он пересылает как есть и не интерпретирует.
